## 專案介紹

台灣已進入超高齡社會，65 歲以上長者失智症盛行率達 7.99%，失智總人口超過 35 萬人。現行認知檢測工具多偏向醫療化，長者容易產生「被檢查」的抗拒感，且缺乏持續使用的誘因；語言表達的細微變化往往比答題數字更能反映日常認知狀態，卻一直缺乏自然、無壓力的方式來留存。

**LightMemory 憶智防線**以長者為主要使用對象，透過三大核心概念設計：

| 概念 | 說明 |
|------|------|
| **遊戲化** | 將六大認知面向的訓練融入「菜市場」主題小遊戲，降低心理抗拒，並以關卡、成就、每日任務培養固定動腦習慣 |
| **可「識」化** | 將遊戲表現、日記語言分析與量表結果整理成易懂的視覺化圖表，讓長者看見進步、家屬及早察覺變化 |
| **AI 化** | 分析長期數據判斷潛在退化趨勢、動態調整遊戲難度、推薦鄰近活動，並對語音描述進行語言層面分析 |

系統分為**長者端**與**家屬端**兩種介面，內容深度與呈現方式依身分調整：長者端以正向鼓勵、淺顯易懂為原則；家屬端提供完整的趨勢分析與健康建議。

## 技術清單

| 類別 | 技術 | 說明 |
|------|------|------|
| 前端框架 | **Flutter (Dart)** | 開源跨平台框架，撰寫一份程式碼即可在 Android、iOS、Web 建立一致的 UI |

## 系統架構

本專案採**前後端分離**架構。Flutter 端不直接接觸資料庫，所有資料皆透過 REST API 取得。

```
┌──────────────────────────────────┐
│      Flutter（本專案）            │
│                                  │
│   features/*/pages（畫面）        │
│              ↓                   │
│   features/*/services（資料層）   │
│              ↓                   │
│   core/network（連線設定）        │
└──────────────┬───────────────────┘
               │  HTTP / JSON
               ↓
┌──────────────────────────────────┐
│      Django REST API             │
│              ↓                   │
│   PostgreSQL / Firebase Storage  │
└──────────────────────────────────┘
```

**分層原則：** 畫面只跟 `services` 要資料，不直接發 HTTP 請求。
後端網址或 API 格式變動時，只需修改 `services` 與 `core/network`，畫面完全不受影響。

**開發策略：** 後端 API 尚未完成前，前端可先在 `services` 回傳假資料（mock data）進行 UI 開發，待 API 完成後替換為真實呼叫即可，兩邊不必互相等待。

## 模組說明

### `auth` — 會員管理

負責使用者身分管理與帳號連動，並整合首次使用所需的篩檢與導覽流程。

| 功能 | 說明 |
|------|------|
| 身分選擇 | 首頁提供「長者模式」與「家屬模式」兩種入口，選擇後進入對應介面 |
| 長者註冊 | 必填：帳號、密碼、生日、性別、居住地區；選填：電話、電子郵件、興趣喜好、家屬聯絡人。興趣喜好將作為資訊加油站的推薦依據 |
| 家屬註冊 | 除基本資料外，另提供綁定機制，填入長者的 User ID 完成綁定，即可查看長者的儀表板數據 |
| AD-8 篩檢量表 | 首次進入系統時進行，題目改編自 AD-8 極早期失智症篩檢量表，以生活化語句降低醫療問卷的壓迫感。歷次結果存入儀表板供長期比對 |
| 新手教學 | 引導頁面依序介紹首頁、聲影日記、資訊站、儀表板、會員中心 |

### `game` — 遊戲系統

以長者熟悉的「菜市場」為統一主題情境，涵蓋六大認知訓練類別，每類別皆設計初階、中階、困難三種難度。首次進入時進行簡短前測，記錄反應速度與正確率作為初始難度基準，後續依實際表現動態調整。

| 認知類別 | 遊戲名稱 | 玩法核心 | 難度調整方式 |
|----------|----------|----------|--------------|
| 注意力 | 今天去菜市場 | 俯視地圖上依編號順序連線規劃採買路線；進階版加入「時間牌」交替連線 | 攤位數 5→10 個，困難關卡加入時間牌交替 |
| 注意力 | 錢包不見了 | 貓咪與草叢中短暫閃現錢包圖示，須在消失前點擊；進階版加入干擾物 | 閃現時間 2 秒→0.8 秒，干擾物 0→4 個 |
| 執行功能 | 整理菜籃 | 長按食材拖曳至分類籃，分類規則持續切換（種類→顏色→能否生吃→混合） | 四階段共 42 題，籃數 2～3 個 |
| 語言 | 家人的購物清單 | 播放語音購物清單後，從 6～9 張食材圖片中點選聽到的品項 | 品項數 2～4 個、選項 6～9 張、含相似食材干擾、語速加快 |
| 工作記憶 | 煮菜過程 | 湯鍋與炒鍋同步進行，依語音提示點擊對應烹飪區；進階版引入 N-Back 模式 | 烹飪道數 1～2 道、記憶深度 0～2 步、提示方式 |
| 數學 | 市場買菜 | 固定預算內採購清單食材，即時計算累計花費；進階版加入找零環節 | 預算 $100～$200、品項 2～4 樣、含 $5 尾數與大小包比較 |
| 視覺空間 | 冰箱清點 | 依語音指示在分層冰箱中尋找食材或回答位置關係；進階版加入拖放任務 | 食材 6～15 種、任務類型、相似食材干擾 |

**回饋設計原則：** 答對時閃綠光搭配輕快音效；答錯時自動退回原位、閃黃光，**全程不出現「錯誤」字樣**，降低長者挫折感。

**回饋機制：**

| 機制 | 說明 |
|------|------|
| 每日任務 | 每日自動指派 3 項，難度與類型由 AI 依近期表現生成。全數完成後任務圈亮起並給予點數 |
| 成就系統 | 分「訓練類」「探索類」「里程碑類」三大類，解鎖時 AI 小助手主動送出祝賀語，徽章集中展示於會員中心 |
| 點數回饋 | 可兌換虛擬勳章或遊戲主題外觀（如節慶版菜市場場景），不涉及真實金錢交易。每日完成上限固定，避免過度使用 |

### `diary` — 聲影日記

結合生活記錄與認知觀察的複合式功能，讓長者在不察覺被評估的狀態下提供認知健康參考資訊。

| 流程 | 說明 |
|------|------|
| 上傳照片 | 從相簿選擇一張日常生活照片 |
| 語音描述 | 以語音描述拍攝地點、當時情境、照片中人物等，**單次錄音上限 3 分鐘** |
| AI 互動 | AI 小助手給予溫暖回應並適時追問延伸問題，**每次僅提出一個問題、最多來回 3 次** |
| 分享選擇 | 完成後可自行決定是否分享至動態牆；不分享則僅作私人記錄保存 |
| 動態牆互動 | 分享後家屬端可看到內容並按讚、留言。遊戲成績紀錄亦可分享至動態牆 |

**認知觀察指標**（由後端分析）：語言組織的流暢度與邏輯性、關鍵細節提取完整度（人名、地點、時間）、描述內容與照片的相符程度。長期累積後比對同類型場景的歷次描述品質變化，作為語言與記憶能力的輔助追蹤依據。

### `dashboard` — 健康儀表板

整合遊戲分數、聲影日記語言分析與 AD-8 量表結果，多面向綜合評估認知健康狀態。依使用者身分分為兩種版本，**建議分成兩個獨立頁面實作**，共用的圖表元件放在 `dashboard/widgets`。

**長者端**（`elder_dashboard_page.dart`）— 淺顯易懂、正向鼓勵為原則

| 區塊 | 內容 |
|------|------|
| 上方 | AI 小助手鼓勵語（例如「最近表現不錯！繼續維持哦～」） |
| 中段 | 腦年齡估算，依綜合表現換算為直觀數值，附簡短文字解譯 |
| 下段 | 六大認知類別雷達圖 + 週報表 / 月報表，各圖表皆附淺顯文字說明 |

**家屬端**（`family_dashboard_page.dart`）— 提供完整分析深度

| 區塊 | 內容 |
|------|------|
| 基本 | 腦年齡估算、六大認知雷達圖、週／月報表 |
| 認知趨勢分析折線圖 | 呈現各認知面向長期變化走勢 |
| 答題正確率分析單元圖 | 以六大類別為列，每題結果依序排列為連續方格；**答對綠色、答錯橘色**，可觀察答對比例與錯題分布 |
| 健康改善建議 | 依整體表現提供日常支持方式的建議 |

### `info` — 資訊加油站

由後端透過爬蟲定期蒐集政府開放資料平台與社區活動網站資訊，再以 AI 自動分類標籤與地理定位。依內容性質分為三大區塊：

| 區塊 | 內容 |
|------|------|
| 活動 | 細分九類：健康講座、運動健身、藝術創作、數位學習、音樂表演、旅遊戶外、語言學習、心靈成長、志工服務。依註冊時填寫的興趣喜好與所在地區個人化推薦，可一鍵串接地圖導航、加入收藏 |
| 機構 | 醫院、長照機構、日間照顧中心等，提供地理位置、聯絡方式與服務內容說明 |
| 資訊 | 衛教知識與健康時事，如季節性疾病預防、營養保健、用藥安全 |

### `assistant` — AI 小助手

以對話介面貫穿整個系統，扮演引導者與陪伴者角色。

| 場景 | 行為 |
|------|------|
| 遊戲系統 | 引導選擇關卡；「整理菜籃」規則切換前以動畫加語音說明新規則 |
| 聲影日記 | 給予溫暖回應並延伸追問 |
| 資訊加油站 | 解說活動資訊 |
| 健康儀表板 | 給予正向鼓勵語 |
| 動態牆 | 對分享的遊戲紀錄主動給予鼓勵性留言 |
| 操作協助 | 遇到困難時提供步驟說明 |

**設計原則：** 語氣溫和、句子簡短，避免過於正式或資訊量過大。**不主動提及疾病或風險**，以正向引導為主軸。

## 使用者流程

> **規劃中** — 以下為預定流程，尚未實作。

### 首次使用（長者）

```
身分選擇 (/)
    ↓ 選擇「長者模式」
註冊 (/register)
    ↓ 必填：帳號、密碼、生日、性別、居住地區
    ↓ 選填：電話、信箱、興趣喜好、家屬聯絡人
AD-8 篩檢量表 (/ad8)
    ↓ 生活化語句呈現，結果存入儀表板作為長期比對基準
新手教學 (/tutorial)
    ↓ 依序介紹：首頁 → 聲影日記 → 資訊站 → 儀表板 → 會員中心
首頁 (/home)
```

### 聲影日記

```
聲影日記首頁 (/diary)
    ↓ 點擊「開始記錄」
上傳照片 (/diary/photo)
    ↓ 從相簿選擇一張生活照片
語音錄製 (/diary/record)
    ↓ 語音描述照片內容（上限 3 分鐘）
    ↓ AI 小助手給予溫暖回應 + 延伸追問（每次一題，最多 3 次來回）
完成頁 (/diary/finish)
    ↓ 選擇是否分享至動態牆
    ├─ 分享 → 動態牆 (/diary/wall)，家屬端可按讚留言
    └─ 不分享 → 僅作私人記錄保存
    ↓ 後端分析語言流暢度、細節提取、圖文相符程度
    ↓ 分析結果併入健康儀表板趨勢圖
```

### 遊戲系統

```
遊戲首頁 (/game)
    ↓ 首次進入 → 簡短前測，記錄反應速度與正確率作為初始難度基準
    ↓ 選擇認知類別（注意力 / 執行功能 / 語言 / 工作記憶 / 數學 / 視覺空間）
    ↓ 選擇難度（初階 / 中階 / 困難，或由系統依表現推薦）
遊戲進行 (/game/play)
    ↓ AI 小助手說明玩法規則
    ↓ 答對閃綠光 + 音效；答錯退回原位 + 閃黃光（不顯示「錯誤」字樣）
成績結算 (/game/result)
    ↓ 顯示分數、正確率、發放點數
    ↓ 可選擇分享成績至動態牆
    ↓ 達成條件時解鎖成就，AI 小助手送出祝賀語
成就與點數 (/game/achievement)
    ↓ 檢視已解鎖徽章、兌換虛擬勳章或遊戲主題外觀
```

### 家屬端

```
家屬註冊 (/family/register)
    ↓ 填入長者 User ID 完成綁定
健康儀表板 (/family/dashboard)
    ↓ 腦年齡、雷達圖、週／月報表
    ↓ 認知趨勢分析折線圖
    ↓ 答題正確率分析單元圖（答對綠 / 答錯橘）
    ↓ 健康改善建議
動態牆 (/family/wall)
    ↓ 檢視長者分享的日記與遊戲紀錄，按讚、留言互動
```

## 開發規範

### 1. 頁面不直接呼叫 API

畫面只跟 `services` 要資料，由 `services` 負責呼叫後端。後端網址或 API 格式變動時，只需修改 `services`，畫面完全不受影響。

```dart
// ✅ 正確
final diaries = await DiaryService.getDiaries();

// ❌ 錯誤 — 畫面裡直接發 HTTP 請求
final response = await http.get(Uri.parse('http://.../api/diary'));
```

### 2. 顏色與字級一律使用 core/theme 定義

> `core/theme` 待設計定案後建立，目前尚未有可引用的定義。

```dart
// ✅ 正確
Text('標題', style: AppTextStyles.h1)
Container(color: AppColors.primary)

// ❌ 錯誤 — 直接寫死數值
Text('標題', style: TextStyle(fontSize: 32))
Container(color: Color(0xFF4A7C7E))
```

### 3. 檔案命名一律小寫加底線

```
✅ home_page.dart      elder_dashboard_page.dart
❌ HomePage.dart       elder-dashboard-page.dart
```

類別名稱則使用大駝峰：`class HomePage extends StatelessWidget`

### 4. 只修改自己負責的模組

各自在 `features/` 底下負責的資料夾內開發，減少 Git 衝突。
若需修改 `core/` 或 `shared/`（全專案共用），**請先在群組告知其他人**。

### 5. 長者介面注意事項

本專案主要使用者為長者，UI 實作時請留意：

- 字級普遍放大，內文建議 18pt 以上
- 按鈕點擊區域加大，避免誤觸
- 避免使用灰色低對比文字
- 錯誤提示以正向語句呈現，避免「錯誤」「失敗」等字樣

## 分支規則

| 分支 | 用途 |
|------|------|
| `main` | 穩定版本，僅透過 PR 合併，不直接推送 |
| `dev` | 開發主線 |
| `feature/xxx` | 個人功能分支 |

### 開發流程

```bash
# 1. 從 dev 開新分支
git checkout dev
git pull
git checkout -b feature/diary-upload

# 2. 開發完成後推上去
git add .
git commit -m "新增聲影日記照片上傳頁面"
git push -u origin feature/diary-upload

# 3. 到 GitHub 發 PR 回 dev，由組長 review 後合併
```

### Commit 訊息慣例

以中文動詞開頭，簡述本次改動內容：

```
新增聲影日記照片上傳頁面
修正首頁字級過小問題
調整儀表板雷達圖配色
```
